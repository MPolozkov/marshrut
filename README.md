# Маршрут

Облачная система для курьерских служб и складов с white-label. Одна установка обслуживает много компаний, каждая работает под своим названием, цветом, логотипом и поддоменом.

## Что умеет

| Модуль | Возможности |
|---|---|
| Единое приложение | Первый экран: «Я заказчик» или «Я курьер». Push-уведомления вместо SMS |
| Заказчик (физлицо) | Вход по SMS, анкета, проверка карты 1 ₽, калькулятор: улица/дом/квартира, GPS, вес и габариты, транспорт, сумма сразу; резерв на карте, курьер на карте в реальном времени, код для получателя, оценка и чаевые картой |
| Организация | Кабинет `/admin`: доставки вручную, из Excel и по API, карта компании, отчёты, сотрудники, интеграции |
| Курьер-самозанятый | Регистрация с ИНН, заказы рядом волнами с push, «Беру» — первому, «Забрал», «Доставлено» только у адреса, заработок, вывод по СБП с чеком «Мой налог», навигатор, сканер, офлайн |
| Деньги | Сумма по тарифу города, % платформе и курьеру, резерв → списание при вручении, возврат при отмене, долг блокирует заказы |
| Владелец платформы | `/platform`: курьеры, тарифы городов, организации, финансы, обращения |
| Предложения | «Что доработать в системе» на сайте и в приложениях — письмо на SUPPORT_EMAIL |
| Для получателя | Ничего не платит; страница отслеживания, push — если установлено приложение |

## Как устроена работа нескольких компаний

1. **Компания регистрируется сама** на `/register`: название, город, телефон, нужные разделы (Склад, Кадры). Название сразу появляется в шапке кабинета, в приложении курьера, в SMS клиентам и на странице отслеживания. Создаются зоны доставки в указанном городе и код для курьеров.
2. **Курьеры регистрируются в приложении** по коду компании (8 символов, виден во вкладке «Курьеры» и в «Настройках»). Заявка приходит диспетчеру, он подтверждает её и выбирает зону.
3. **Заказы приходят автоматически** — через API по ключу компании (интернет-магазин, 1С, CRM) или загрузкой файла из Excel. Ручной ввод остаётся для разовых заказов. Статусы уходят обратно в систему клиента по вебхуку.
4. **Владелец платформы** видит все компании и обращения в панели `/platform`: активность, тарифы, блокировка, вход в кабинет от имени владельца для поддержки.

| Адрес | Что это |
|---|---|
| `/` | Главная: как работает, как считается сумма, форма поддержки |
| `/register` | Регистрация организации-заказчика (без абонентской платы) |
| `/order` | Веб-версия заказа для физлиц |
| `/admin` | Кабинет организации (вход `/admin/login`) |
| `/admin/support` | Техподдержка и заявка на бесплатное подключение |
| `/platform` | Панель владельца платформы |
| `/track/НОМЕР` | Отслеживание для получателя |

## Стек

| Часть | Технологии |
|---|---|
| Сервер | Node.js 22, NestJS 10, Drizzle ORM, PostgreSQL 16 + PostGIS |
| Очереди | Redis 7 + BullMQ (уведомления с повторными попытками) |
| Веб-кабинет | React 18, Vite, React Router |
| Мобильное приложение (заказчик и курьер) | React Native, Expo SDK 58, сборка APK через EAS |
| Развёртывание | Docker Compose, сервер в РФ (Selectel, Yandex Cloud, VK Cloud) |

```
apps/api       сервер и REST API
apps/web       веб-кабинет (диспетчер, склад, кадры, владелец) и страница трекинга
apps/courier   единое мобильное приложение: «Я заказчик» / «Я курьер»
scripts/       резервное копирование
```

## Быстрый старт (локально)

Нужны Node.js 22 LTS и Docker. База в Docker слушает порт **5433**, чтобы не конфликтовать с установленным PostgreSQL.

```bash
cp .env.example .env            # заполните JWT_SECRET
docker compose up -d db redis   # база и Redis

npm install                     # из корня: ставит api и web
npm run db:generate             # один раз: создаёт SQL-миграции в apps/api/drizzle
npm run build -w apps/api
npm start -w apps/api           # применит миграции и запустит API на :3000
npm run db:seed                 # демо-компания

npm run dev:web                 # кабинет на http://localhost:5173
```

Демо-доступы, пароль у всех `demo12345`: организация «Магазин Демо» — `owner@demo.ru`, `dispatcher@demo.ru` (кабинет `/admin`); курьеры-самозанятые — `courier@demo.ru` (легковой), `driver@demo.ru` (грузовой). Заказчик-физлицо — мобильное приложение, «Я заказчик», вход любым номером (код показывается на экране, пока SMS не подключены), или веб `/order`.

Тесты калькулятора: `npm run build -w apps/api && npm test -w apps/api`.

## Мобильное приложение (заказчик и курьер)

Одно приложение для всех: на первом экране выбор «Я заказчик» или «Я курьер», выбор запоминается (сменить — «Выйти»).

```bash
cd apps/courier
npm install
npx expo install --fix          # подгоняет версии пакетов под Expo SDK, в т. ч. новый expo-web-browser (в папке есть .npmrc с legacy-peer-deps)
npx expo start                  # открыть в Expo Go на телефоне или в эмуляторе
```

Адрес API и бренд задаются в `app.json` → `expo.extra` (`apiUrl`, `brandName`, `brandColor`). Для телефона в той же Wi-Fi сети укажите IP компьютера (`ipconfig`), например `http://192.168.0.102:3000/api`, и откройте порт 3000 в брандмауэре Windows. Если на компьютере включён VPN, запускайте Expo с `REACT_NATIVE_PACKAGER_HOSTNAME=<IP>`.

**Сборка APK для RuStore и раздачи напрямую:**

```bash
npm install -g eas-cli
eas login
npm run build:apk               # тестовая сборка
npm run build:release           # для публикации
```

Готовый APK загружается в кабинет разработчика RuStore. Для публикации с платежами RuStore нужен статус ИП или юрлица.

**White-label сборка для клиента:** поменяйте в `app.json` название, `android.package` (например `ru.bystro.courier`), иконку `assets/icon.png` и `extra`, затем соберите отдельный APK.

Без сети приложение сохраняет вручения и отказы в телефоне и отправляет их при появлении связи. Сервер принимает повтор без дублей. Код вручения в этом случае проверяется при отправке: если он неверный, курьер увидит ошибку в списке и переделает отметку.

## Продакшен

```bash
npm install && npm run db:generate   # миграции коммитятся в репозиторий
docker compose up -d --build         # кабинет на :8080, API за nginx на /api
docker compose exec api node dist/db/seed.js   # по желанию, демо-данные
```

- Перед кабинетом поставьте HTTPS (Caddy или nginx + Let's Encrypt).
- Для white-label на поддоменах нужна wildcard-запись `*.ваш-домен.ru` и wildcard-сертификат. Страница входа на `bystro.ваш-домен.ru` сама подхватит бренд компании со slug `bystro`.
- Резервные копии: `scripts/backup.sh` в cron (база и фото, хранит 14 копий). Копии выносите на другой сервер или в S3.
- Проверка живости: `GET /api/health`.
- Фото вручений лежат в томе `uploads`. Для нескольких серверов замените `StorageService` на S3-совместимое хранилище.

## Обновление с прошлой версии

В этой версии изменилась структура базы. Проще всего пересоздать тестовую базу (демо-данные создадутся заново):

```bash
docker compose down -v && docker compose up -d db redis
npm install
npm run db:generate             # в новом архиве папки apps/api/drizzle нет — она создастся с нуля
npm run build -w apps/api && npm start -w apps/api
npm run db:seed
```

Если в базе уже есть настоящие данные, перенесите папку `apps/api/drizzle` из старой версии **до** `db:generate` — тогда создастся только новая миграция с изменениями.

## Панель владельца платформы

Задайте в `.env` `ADMIN_EMAIL` и `ADMIN_PASSWORD`, перезапустите сервер и откройте `/platform`. Без этих переменных панель выключена.

## Тарифы

Цены, лимиты и описание тарифов — в `apps/api/src/plans.ts`. Их показывают главная страница, регистрация и настройки кабинета. Пробный период — `TRIAL_DAYS` (14 дней). Сменить тариф компании и продлить бесплатный период можно в `/platform`. Лимиты тарифов пока только показываются, автоматически не ограничиваются.

## Техподдержка и почта

Обращения с главной страницы и из кабинета сохраняются в базе (вкладка «Обращения» в `/platform`) и отправляются письмом на `SUPPORT_EMAIL` (по умолчанию pipl82308@gmail.com). Клиенту приходит подтверждение с номером обращения; чтобы ответить ему, достаточно ответить на письмо.

Для отправки писем заполните SMTP в `.env`. Для Gmail:
1. Включите двухэтапную аутентификацию в аккаунте Google.
2. Создайте «Пароль приложения»: myaccount.google.com → Безопасность → Пароли приложений.
3. `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, `SMTP_USER=pipl82308@gmail.com`, `SMTP_PASS=<пароль приложения>`.

В заявке на подключение клиент указывает систему, что и куда передавать, объём заказов и отмечает, какие доступы готов предоставить. Сами пароли и ключи форма не принимает — их запрашивают у клиента отдельно.

## Интеграции (приём заказов от клиентов)

Владелец выпускает API-ключ во вкладке «Интеграции» — там же готовый пример запроса для программиста.

```bash
curl -X POST https://ваш-домен/api/integration/v1/orders \
  -H "Authorization: Bearer mr_live_…" -H "Content-Type: application/json" \
  -d '{"externalId":"ORDER-1042","recipient":{"name":"Мария Котова","phone":"+79131234567"},"city":"Новосибирск","address":"ул. Ленина, 12","weightKg":2.5,"codRub":1500}'
```

- Повтор с тем же `externalId` не создаёт дубль — безопасно отправлять заказ повторно при сбое связи.
- Зона подбирается по городу (или полю `zone`), стоимость — по тарифам компании.
- Вебхук: POST на адрес клиента при создании и каждой смене статуса, подпись `X-Marshrut-Signature` (HMAC-SHA256 секретом из «Интеграций»), до 4 повторов.
- Без программиста: «Накладные» → «Загрузить заказы из Excel» (CSV, UTF-8 или Windows-1251, колонки на русском).

## Города

Подсказки городов работают по встроенному списку крупных городов России. Для поиска любого населённого пункта задайте `DADATA_API_KEY` (бесплатный тариф dadata.ru). Компания может работать в нескольких городах: добавьте зоны для нового города в «Настройках», и в накладной и калькуляторе появится выбор города.

## Как работает платформа (v0.9)

Курьеры-самозанятые работают напрямую с платформой. Заказы физлиц (мобильное приложение, роль «Я заказчик», или веб `/order`) и организаций (кабинет `/admin`, файл Excel, API) сразу уходят курьерам рядом. Пакетов и подписок нет — платформа зарабатывает процент с каждого заказа. Получатель ничего не платит.

**Сумма заказа** (одна для всех, по тарифу города; тарифы задаёт владелец в `/platform` → «Тарифы доставки»):

> подача (по виду транспорта) + километры по дороге × ставка + каждый кг сверх включённых × ставка; с 22:00 до 7:00 — ночная надбавка (по умолчанию +20%); округление до 10 ₽.

Расстояние — по координатам адресов (GPS заказчика или геокодер Яндекса `YANDEX_GEOCODER_KEY`) × 1,25 на дороги; без ключа по городу считается 8 км. Транспорт: пеший (до 5 кг), вело/самокат (до 15 кг), легковой (до 300 кг), грузовой 3,5–5 т (до 2 т).

**Деление суммы:** платформе `PLATFORM_FEE_PERCENT` (по умолчанию 50%), курьеру — остальное. Комиссия эквайринга (~2–3%) — из доли платформы. Пример: легковой, 7 км, 10 кг днём — 450 + 7 × 35 = 700 ₽; курьер 350 ₽, платформа 350 ₽.

**Оплата только картой заказчика** (ЮKassa, двухстадийные платежи; без ключей — тестовый режим):
1. Физлицо привязывает карту при регистрации, организация — в «Настройках» кабинета (проверка: резерв 1 ₽ и сразу отмена).
2. Оформление заказа → сумма **резервируется**. Если банк просит 3-D Secure — страница банка, потом проверка. Не подтверждено за `PAY_WAIT_MINUTES` (30) — заказ отменяется.
3. Резерв прошёл → заказ сразу виден курьерам-самозанятым в этом городе с подходящим транспортом (сначала ближайшим), им приходит push. Везёт первый, кто нажал «Беру».
4. **«Доставлено»** доступно курьеру только ближе `DELIVER_RADIUS_M` (300 м) к адресу доставки — проверяют и приложение, и сервер; получатель называет код (его видит заказчик в приложении). В этот момент сумма **списывается**, курьеру начисляется его доля.
5. Отмена до забора — резерв снимается, деньги возвращаются на ту же карту. Не списалось после вручения — повторная попытка, иначе долг: новые заказы недоступны, пока не погашен.
6. Чаевые — списанием с карты, курьеру целиком.

**Адрес доставки** обязателен по полям: улица, дом, квартира/офис (или «частный дом»); подъезд, этаж, домофон — по желанию. Курьер видит его полностью. В CSV — колонки «Улица», «Дом», «Квартира»; в API — объект `address: { street, house, apartment, entrance, floor, intercom }`.

**Заказчик видит курьера на карте** в реальном времени (приложение курьера с заказом на руках отправляет точку каждые 15 секунд).

**Уведомления — push из приложения вместо SMS** (Expo Push): заказчику (курьер найден, забрал, доставлено, оплата не прошла), курьеру (новый заказ рядом с суммой, чаевые), получателю — если у него установлено приложение с тем же номером. SMS остаётся только для кода входа. Push работают в собранном приложении (APK/development build): в `app.json` → `extra.eas.projectId` нужен id проекта EAS (`eas init`). В Expo Go на Android удалённые push недоступны — экраны и так обновляются сами.

**Курьеры-самозанятые.** Регистрация в приложении «Я курьер» с ИНН (без кода компании) → владелец платформы подтверждает в `/platform` → «Курьеры». В настройках курьер подключает «Мой налог» (разрешение платформе формировать чеки), указывает телефон и банк для СБП и выводит деньги кнопкой «Вывести» — через ЮKassa «Выплаты» (`YOOKASSA_PAYOUT_AGENT_ID`, `YOOKASSA_PAYOUT_SECRET`), чек формируется автоматически. Без ключей — тестовые выплаты.

**Панель владельца `/platform`:** курьеры (подтверждение, «Мой налог», баланс), тарифы по городам, организации, финансы (доход платформы, оплаты, выплаты, балансы курьеров, долги), обращения.
